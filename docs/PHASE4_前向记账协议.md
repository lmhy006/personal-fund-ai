## 1. 必须先写清楚的口径差异（审计发现）

| 位置 | 现存表述 | 实际实现 |
|---|---|---|
| `live_portfolio.py` 顶部注释 | "在持 cohort 权重**不做月度再平衡**（自然漂移，与回测一致）" | 本模块只维护**建仓时的目标权重**，不计算收益，也不做份额漂移模拟 |
| `backtest_strategy.py` | 收益聚合 | 对各基金**当月收益求简单均值**，再对 cohort 求均值（等权算术聚合，**未**使用漂移后的份额权重） |

**两者不能声称"在六批 cohort 到齐后自动完全一致"。** 反例（两基金各 50%）：

- 第 1 个月：A 涨 100%、B 不变 → 真实份额权重变为 A 2/3、B 1/3；
- 第 2 个月：B 涨 100%、A 不变 → **自然持有（漂移）收益 = 1/3**，而**等权当月均值 = 1/2**。

历史回测成绩按等权算术口径产生，**不得**用漂移口径重算后宣称与既有结论一致；反之，前向纸面若采用漂移口径，必须与历史成绩**分列对账**并注明口径差异。

## 2. 前向账本规格（首次模拟成交时一次性固定）

1. **初始资本与成交要素**：固定初始资本；逐笔记录买入金额、成交净值、份额、`BUY_FEE=0.15%` 申购费、到期赎回 `SELL_FEE=0.5%`；现金部分按既定 **2%/年** 计息。
2. **收益口径**：一律使用**官方日增长率**（净值表 `日增长率` 字段）累计，**不得**改用累计净值 `pct_change`（分红除权口径不同）。
3. **可执行全池对照**：固定入池集合（入池日、数据时点、费用口径与主策略一致）；前五个月按 1/6 递进建仓，**现金差异如何比较必须单独说明**（历史 warm-up 用 `1/n_held` 等权、未建模现金，与前向方案 A 语义不同）。
4. **对照目标**：主策略检验的是**相对可执行全池**的表现；只有影子方案才检验"相对原动量的配对增量"。原动量不能以"比自己有增量"作为验收条件。
5. **统计纪律**：沿用既定冻结纪律与 **NW(6)** 自相关稳健 t 值；126 交易日标签、六个日历月 cohort、实际执行区间**分别记录**，不凭 "2027-03" 猜成熟。

## 3. 与执行确认的关系

- `confirm_execution` 只把 cohort 从 `planned` 改成 `active` 并写不可变执行事件——**不产生任何收益数字**；
- 账本（`src/paper_ledger.py`）**只为已确认的执行建仓**：非预演模式下若该 cohort 无执行确认事件（或
  `execution_date` 与事件不一致）会直接拒绝；`--dry-run` 预演写入 `ml/paper/dryrun/` 并标 `simulated=true`，
  绝不冒充真实执行留痕；
- 即使账本已算出净值曲线，`ml/ledger/portfolio_state.json` 里的 `cash_weight`/`target_weights` 仍只是
  **目标权重**；任何"前向收益"结论都须等成熟样本门槛（第 4 节），并显式标注账本口径与历史口径的差异。

### 账本用法（最小实现，2026-10-02 加固后）

```bash
# 10-8 确认执行后建仓（要求已存在执行确认事件，且日期与事件**来源 run_id** 一致）
python src/paper_ledger.py --open --execution-date 2026-10-08
# 纯计算（不写盘、不要求确认；诊断/试算用）
python src/paper_ledger.py --open --execution-date 2026-10-08 --no-save
# 预演（不要求确认，写 ml/paper/dryrun/ 并标 simulated）
python src/paper_ledger.py --open --execution-date 2026-09-30 --dry-run
# cohort 估值（官方日增长率复权累计 + 现金计息；迟发记 stale_days）
python src/paper_ledger.py --value 2026-10-09
# 组合层汇总（Σ cohort_nav×权重 + 未投资现金计息，不写盘）
python src/paper_ledger.py --portfolio 2026-10-09
# 估值修订（默认拒绝覆盖不同内容；确需修订才用，会备份旧版并记录原因）
python src/paper_ledger.py --value 2026-10-09 --revision --revision-reason "净值数据更正后重算"
```

产物：`ml/paper/ledgers/paper_ledger_{cohort}.json`（建仓明细：金额/申购费/净申购额/份额/成交净值/
迟发 lag_days/执行事件来源）、`ml/paper/ledgers/valuation_{cohort}_{as_of}.json`（逐只市值、复权因子、
最后净值日、**数据指纹 data_hashes**、现金计息、cohort 净值）。修订版本备份为 `*.rev_{n}`。

**不可变与可核验**（2026-10-02 加固 + 三次复核）：
- 账本/估值相同内容重跑幂等返回 `existing`；**内容不同拒绝覆盖**；差异判定以**实际参与估值的数据切片**
  （`data_hashes[*].slice_sha256`，区间 `(建仓成交日, 估值日]`）为准，整文件哈希仅作来源记录
  `nav_file_sha256`——因此"估值日之后追加净值"不会误判为变化，而"估值区间内数据被改动"仍会被检出；
- 建仓**绑定来源**：执行事件的 `source_run_id` 必须**存在且等于**封存输入的 `run_id`（缺失直接拒绝）；
- **诊断身份**：`persist=False`（纯计算）与 `--dry-run`（预演）产物带 `diagnostic=true`，只能落
  `ml/paper/dryrun/`；正式估值落盘前**再次**核对执行事实，未确认执行的计算结果无法以正式身份写盘；
- **待定估值**：若某基金成交净值日**晚于**估值日（建仓尚未发生），默认拒绝出估值；`allow_pending=True`
  只用于诊断并标 `status=pending`，不会出现 `stale_days=-1`，也不得落盘为完成估值；
- 建仓请**显式指定封存输入**：`--inputs ml/paper/paper_inputs_20260930_233855.json`（避免误取最新一份）。

## 3.1 口径：cohort 净值 ≠ 组合净值（2026-10-02 用户指正）

- **cohort 净值**（`value()` 的 `cohort_nav`）：以**该 cohort 的资本**（1/6）为分母，起点 1.0；
  建仓日无价格变化时 = `1 − buy_fee` = **0.9985**。此前代码与输出把它称为"组合净值"，是**错误**的。
- **组合净值**（`portfolio_value()` 的 `portfolio_nav`）：`Σ(cohort_nav × cohort_weight) + 未投资现金计息`。
  单 cohort、建仓日无价格变化、尚无利息时：

  \[
  \frac16(1-0.0015)+\frac56 = \mathbf{0.999750}
  \]

  即"申购费只作用在建仓的那 1/6 上，另外 5/6 仍是现金"。当前阶段（仅 2026-09 一个 cohort）
  组合净值 ≈ cohort 净值 × 1/6 + 5/6，**两者相差很大，不可混用**。
- 现金计息：2%/年 actual-365 日复利，**按现金流逐段计息**——时间轴上先计息到各 cohort 的建仓日，
  再扣除其投入资本（`cash_segments` 给出逐段明细）。两批相隔 32 天、基金收益为零时组合净值
  = **1.000962429**；若按"最终剩余现金从最早建仓日整段计息"会少计约 **2.93bp**（得 1.000669943）。
